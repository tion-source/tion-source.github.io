역할튜터 — 커리큘럼 설계, 하드웨어·SW 환경 구성 지도, 문제 해결 루틴 운영

사람이 리더 팔을 움직이면 팔로워 팔이 따라 하는 Teleoperation으로 시연 데이터를 모으고, 그 데이터로 로봇이 같은 동작을 스스로 재현하도록 Imitation Learning(ACT) 모델을 학습시켰습니다. 8주 동안 조립부터 학습까지 전 과정을 튜티들과 함께 진행했습니다.

W1–2LeaderArm · FollowerArm 조립, Ubuntu 개발 환경과 udev 규칙 구성
W3–4Calibration, Teleoperation 설정, 카메라 포트 고정
W5–6lerobot-record로 30개 이상 에피소드 수집, Replay 검증·품질 라벨링
W7–8ACT 모델 학습, 데이터셋 시각화·편집 후 HuggingFace 업로드
01 · Hardware — Leader / Follower Arm

구성

  • SO-ARM 리더 팔 + 팔로워 팔 한 쌍을 3D 프린팅 부품과 Feetech 서보로 직접 조립
  • 관절 6개 — shoulder_pan · shoulder_lift · elbow_flex · wrist_flex · wrist_roll · gripper
  • 카메라로 작업 영상을 함께 기록 (관절 값 + 영상 = 학습 데이터)

설계 핵심

  • USB 포트 고정 — 팔 2개와 카메라를 꽂을 때마다 포트 이름(/dev/ttyACM*)이 바뀌어 설정이 꼬임 → udev 규칙으로 장치별 이름을 고정
  • Calibration — 리더·팔로워 팔의 관절별 최소·중간·최대 위치를 기록해 두 팔의 각도 기준을 맞춤. 기준이 틀어지면 Teleoperation부터 어긋나기 때문에 데이터 품질의 출발점
02 · Software — Data → Training

파이프라인

  • 수집 — lerobot-record로 Teleoperation 시연 30개 이상 에피소드 기록
  • 검증 — Replay로 기록한 동작을 다시 재생해 보고, 에피소드별 품질 라벨링
  • 학습 — ACT(Action Chunking with Transformers)로 모방 학습, 학습한 모델로 로봇이 동작을 스스로 재현
  • 정리 — 데이터셋 시각화·편집 → 통계 재계산 → 인덱스 재정렬 후 데이터셋과 모델을 HuggingFace에 업로드

문제 → 해결

  • 카메라 FPS 오류 (W5) — 로그 정리 후 원인 파악, 재현 조건을 기록
  • Swap 메모리 부족 (W6) — 메모리 상태를 먼저 분석하고 swap 설정으로 해결
  • Overfit (W7) — 팀원 3명이 각자 원인 가설을 세워 비교한 뒤, 50,000 step 체크포인트를 적용해 같은 환경에서 성공률 개선
  • 인덱스 결번 (W8) — 데이터셋 편집 후 생긴 결번의 원인 3가지를 정리하고 compute_stats 재실행으로 해결
03 · 튜터로서 바꾼 것
  • Before — 오류가 나면 에러 메시지를 그대로 AI에 붙여 넣고 답을 바로 실행 → USB 포트 설정이 꼬이고, 해결 기록이 남지 않아 같은 오류를 반복
  • After — 「증상 → 가설 → AI 질의 → 검증」 4단계 루틴을 팀 표준으로 정하고, 결정과 근거를 Notion에 기록. AI 답은 참고 자료로만, 채택 여부는 직접 테스트로 결정
